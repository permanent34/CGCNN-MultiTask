# CGCNN 论文汇报笔记

论文：Tian Xie and Jeffrey C. Grossman, *Crystal Graph Convolutional Neural Networks for an Accurate and Interpretable Prediction of Material Properties*, Physical Review Letters, 2018.

## 1. CGCNN 为什么提出？

材料性质通常由晶体结构和元素组成决定。传统机器学习方法往往需要人工设计描述符，而 CGCNN 希望直接从晶体结构中学习表示：

```text
晶体结构 → 晶体图 → 图卷积 → 晶体表示 → 性质预测
```

它的核心目标是：

- 减少人工特征工程；
- 利用晶体中局部原子连接关系；
- 同时适用于回归和分类任务；
- 为材料性质预测提供可解释的局部信息。

## 2. CGCNN 和普通 CNN 有什么区别？

普通 CNN 通常处理图像或规则网格数据，卷积极在规则的二维或三维邻域上移动。晶体结构不是规则网格：

- 原子数量不同；
- 邻居数量不同；
- 结构具有周期性；
- 原子间距离和局部环境不同。

CGCNN 使用图卷积，按照晶体中真实存在的邻居关系传播信息，而不是把晶体强行变成固定网格。

## 3. 为什么晶体可以表示成 Graph？

晶体可以写成：

```text
G = (V, E)
```

- `V`：节点集合；
- `E`：边集合。

晶体中的重复单元可以通过周期性边界条件扩展为局部邻域。每个原子及其近邻可组成一个节点中心子图，因此晶体天然适合使用图神经网络表示。

## 4. Node 和 Edge 分别是什么？

### Node

一个节点代表一个原子。节点初始特征来自 `atom_init.json`：

- 本项目的实际特征长度为 92；
- 特征包含元素种类相关信息；
- 相同元素使用相同初始向量。

### Edge

一条边代表中心原子与邻居原子之间的连接。边特征主要描述二者距离：

- 最大邻居数：12；
- 截断半径：8 Å；
- 高斯距离展开：`dmin=0`、`dmax=8`、`step=0.2`；
- 因此边特征实际为 41 维。

如果近邻不足 12 个，代码使用索引 0 和 `radius + 1` 的距离进行补齐；不够的近邻会触发 warning。

## 5. Graph Convolution 怎么聚合邻居信息？

对中心原子 `i`，把以下三部分拼接：

```text
中心原子特征 v_i
邻居原子特征 v_j
边特征 u_ij
```

然后经过线性变换、Sigmoid 门控、Softplus 和邻居求和，更新中心原子：

```text
v_i^(t+1) = v_i^(t) + Aggregate_j[
    gate(v_i, v_j, u_ij) * core(v_i, v_j, u_ij)
]
```

门的直观作用：

- 决定邻居信息中有多少内容传递给中心原子；
- 不是所有邻居都对最终性质同样重要；
- 多层堆叠后，信息可以传播到更远范围。

本项目实现位于 `cgcnn/model.py` 的 `ConvLayer`：

- `fc_full` 将拼接后的特征映射到两倍原子隐藏维度；
- 一半经过 Sigmoid，作为 gate；
- 一半经过 Softplus，作为核心信息；
- 两部分逐元素相乘后对邻居求和；
- BatchNorm、残差连接和 Softplus 完成更新。

## 6. 怎么从原子特征得到整个晶体的特征？

每个原子经过多层图卷积后得到原子级表示。对同一个晶体中的所有原子表示取平均：

```text
crystal_feature = mean(atom_features)
```

本项目使用 `CrystalGraphConvNet.pooling`。平均 pooling 简单、稳定，但也会丢失部分空间分布信息。

## 7. 最后怎么预测材料性质？

晶体表示经过全连接层：

```text
pooled feature
    ↓
Linear + Softplus
    ↓
可选隐藏层
    ↓
输出层
```

原始回归输出：

```text
Linear(128, 1)
```

本项目的多任务回归输出：

```text
Linear(128, K)
```

其中 K 是目标性质数量。当前三任务版本 K=3。

## 8. CGCNN 有什么优点？

- 直接使用晶体结构，不需要人工设计大量描述符；
- 图卷积符合晶体局部环境的物理直觉；
- 一个模型可支持不同材料性质；
- 训练和推理速度相对高效；
- 通过邻居信息聚合可获得一定的可解释性；
- 论文在 Materials Project 大规模数据上展示了较好的精度。

## 9. CGCNN 有什么局限？

- 只使用截断半径内的局部信息，不显式处理长程静电作用；
- 不直接建模温度、压力、磁性和自旋状态；
- 晶体图构建依赖半径、最大邻居数和距离展开参数；
- 对训练分布之外的材料泛化较差；
- 平均 pooling 会压缩晶体结构信息；
- 模型精度依赖 CIF 和性质标签质量；
- 原始论文主要验证单任务，未解决任务冲突和 negative transfer。

## 10. 我的多任务修改和原始 CGCNN 有什么关系？

相同部分：

- 晶体图构建相同；
- ConvLayer 相同；
- 图卷积层数、原子隐藏维度和 pooling 相同；
- 共享表示仍然来自同一个 CGCNN 主干。

修改部分：

- 输入 CSV 从单标签改为多标签；
- 输出层从 1 维改为 K 维；
- loss 从普通 MSE 改为 mask-aware MSE；
- Normalizer 从整体统计改为按任务统计；
- predict.py 从 checkpoint 中读取任务数。

简化结构：

```text
Crystal Graph
      ↓
Shared CGCNN Backbone
      ↓
Shared Representation
      ↓
One Linear Layer with K Outputs
   ↓          ↓          ↓
Property 1 Property 2 Property 3
```

需要注意：当前版本只是“共享主干 + 多输出”，还没有加入：

- 任务专属 head；
- 动态任务权重；
- 梯度冲突处理；
- 不确定性建模；
- 单任务 vs 多任务的同数据严格对照。

## 汇报时最容易讲错的点

1. 验证集 MAE 不是测试集 MAE。
2. 不同性质的 MAE 不能直接平均后当作唯一结论。
3. 多任务输出 3 个值，不等于三个完全独立的模型。
4. 当前多任务模型尚未证明一定优于单任务模型。
5. `mt-large` 的指标来自 30 轮训练，不能直接和原始论文的长训练结果比较。
6. `predict.py` 当前使用 shuffle，CSV 行顺序不保证固定。

## 一分钟总结

CGCNN 把晶体中的原子和近邻关系构造成图，用图卷积聚合局部环境，再通过 pooling 得到晶体表示并预测性质。原始 CGCNN 主要是一个输出一个性质。我在不改图卷积主干的前提下，把输出层改成 K 维，并处理多标签和缺失值，实现了共享表示的三任务预测。真实结果表明形成能预测较好，带隙和费米能更难；后续需要做同数据单任务对照，才能判断多任务究竟带来了正迁移还是负迁移。
